# スイング・ラリー自動カット（iPhone だけで動く版）

iPhone の Safari で開くだけで使える、ゴルフのスイング切り抜き／テニスのポイント間カットです。
Mac やサーバーは不要で、**動画は iPhone の外に送信されません**。

公開先（GitHub Pages）: `https://air-tomo.github.io/cut/`

## 使い方

1. 上部で「⛳ ゴルフ練習」か「🎾 テニス試合」を選ぶ
2. 動画を選んで「読み込んで検出する」
   - 長い動画は「写真」アプリの共有 →「"ファイル"に保存」してから「ファイル」で選ぶと、変換待ちがなく画質もそのまま
3. 確認・調整
   - 各区間の ▶ で元の動画を再生、チェックを外すと書き出さない
   - 「開始」「終了」の ±0.5 で区間を微調整
   - 「つなげて再生」で書き出し後のイメージを確認
   - 「検出の設定」を変えるとその場で検出し直す（モードの切り替えも、動画を読み直さずにできる）
4. 「書き出す」→「写真に保存・共有」→「ビデオを保存」

## しくみ

- **検出**: 動画から AAC 音声を少しずつ取り出して Safari でデコードし、打球音（10〜20ms の鋭い衝撃音）を探す。
  方法と初期値は `golf-swing-app/`（Mac 版）と同じで、同じ動画なら同じ結果になる
  - ゴルフ: 打球の 3 秒前〜2 秒後
  - テニス: **ポイントはサーブから**。サーブ前のボールつき（1 秒未満のリズムで続く、サーブより小さい音）を除いて
    最初の打球をサーブとし（ボール拾い・足音で前のラリーとつながった場合は、手前の選手の大きな打球が
    9 秒以上なかったあとの大きな打球で区切る）、トス（サーブの 1.5 秒前）から最後の打球の 2 秒後までを残す。
    フォルトのあと 12 秒以内のセカンドサーブは同じポイントにまとめ、間の待ち時間は除く。
    セカンドサーブより 3dB 以上小さい音（サーブ直前のボールつき、隣のコートの打球）はフォルトとせず取り除く
- **書き出し**: 再エンコードせず、映像・音声データをそのままコピーして1本の動画にする。
  画質が落ちず速い（テスト環境で 1 時間の動画を約 2 秒）。データはキーフレーム単位でコピーし、
  実際に見せる範囲は編集リスト（QuickTime の仕組み）で指定するので、区間の始まり・終わりはフレーム単位で正確
  - B フレーム・HEVC のオープン GOP にも対応（つなぎ目の CRA キーフレームを BLA に変換）
  - 編集リストを無視する一部のアプリでは、各区間の前後にキーフレームまでの数フレーム〜数秒が余分に見える
  - 縦向き・HDR（Dolby Vision）の情報もそのまま保たれる
- **保存**: 書き出し中の動画はブラウザ内の保存領域（OPFS）に少しずつ書くので、大きな動画でもメモリ不足になりにくい。
  プライベートブラウズでは保存領域が使えないため、メモリ上で作る（短い動画向け）

## テニス試合解析（試作）: `analyze/`

公開先: `https://air-tomo.github.io/cut/analyze/`

試合動画から、ポイントごとのボールの軌跡・バウンド・イン/アウト・サーブ速度を出す。解析はすべて端末の中（ブラウザ）。

1. 動画とボール検出モデル（.onnx）を選ぶ。モデルは一度選ぶと端末の保存領域（OPFS）に残る。
   モデルは `golf-swing-app/tools/court3d/train_ball_colab.ipynb`（Colab）で作る軽量版を想定
2. 音でラリーの区間を見つける（`detect.js`、カット画面と同じ）
3. コートの位置合わせ: 画面で 4 点（手前のサービスラインの両端・奥のベースラインの両端）と、ネットポストの頂上 2 点をタップ
   （押したまま動かすと拡大鏡）。白線をすべて当てはめてカメラの位置・向きを出す（`court.js`）
4. 区間ごとにボールを追う（`ball.js`: WebCodecs でデコード → ONNX Runtime Web（WebGPU）でボール検出。
   ボールが見つかったら次のフレームは周辺だけを見るので計算は約半分）
5. 試合全体で組み立てる（`rally.js`）
   - バウンド: 画像上で下がってから上がる点（V 字）。落ちる線と上がる線の交点で取り逃しを補う
   - サーブ: 手前の選手は「大きな打球音 → 画面の高い所から奥へ速く下りる球」、奥の選手は「手前のサービスボックス付近へ速く、
     ベースラインで 1.8m 以上の打点」。どちらも直前 4 秒は打球もコート内のバウンドもないこと（ポイント間の返球やスマッシュと区別）
   - フォルト: 返球されず（4.5 秒以内に打球音が 2 回未満）に 25 秒以内にまたサーブ、またはサーブが入った側から判断して
     「同じ側からもう一度」= セカンドサーブ（違う側なら次のポイント）。フォルトとセカンドサーブは 1 ポイントにまとめる
   - イン/アウト: サーブはサービスボックス、それ以外はシングルスのコート。線の近く（手前 ±0.15m、奥 ±0.8m）は「微妙」
   - ポイントの終わり: アウト、またはボールが 2 秒以上見えなくなったとき
   - サーブ速度: 打球音の時刻・打点の事前条件・見えたバウンド地点で 3D の軌道（重力・空気抵抗）を当てはめる
6. 結果の一覧と、軌跡・バウンド・イン/アウト・コート図を重ねた再生。「ポイントだけの動画を書き出す」（再エンコードなし）

Python 版（`golf-swing-app/tools/court3d/tn_post.py`）と同じ方法で、同じ入力から同じポイント・バウンド・判定になることを確かめてある。
速度の目安は `bench/` で測れる（端末の GPU で 1 フレームの処理時間）。

## 撮影の目安

テニスの検出を実際の試合・練習動画（iPhone 11 Pro〜16e、30/60fps）で調整したときに分かったこと。

- 手前の選手の打球は奥の選手より約 10dB 大きく、奥の選手の打球は検出の境目に近い。
  カメラはコートの真後ろ（手前のベースラインの後ろ）に置くと、両方の打球を拾いやすい
- カメラを地面やベンチに置くと、手前のサーバーのボールつき・足音がとても大きく入る（ボールつきは 0.5〜1.4 秒間隔）
- 隣のコートの打球も拾うが、セカンドサーブより小さい音はフォルトと見なさないので、試合の区切りには影響しにくい
- 将来、コート寸法とネットの高さを基準に落下地点・打球地点・球速を出すなら:
  - 高さ 2〜3m 以上から、両方のベースラインと両サイドラインが入るように横向きで撮る
    （地面に置くと奥のコートが細い帯になり、奥の落下地点が分からない）
  - 60fps 以上（球速 150km/h のサーブは 60fps で 1 コマ約 0.7m 進む）。ズーム・向きは撮影中に変えない

## 動作環境

- iOS 16.4 以降の Safari（iOS 26 推奨）
- iPhone で撮影した MOV / MP4（AAC 音声）。それ以外の音声形式は 800MB までの動画のみ

## ファイル

| ファイル | 内容 |
| --- | --- |
| `index.html` | 画面 |
| `app.js` | 画面の操作、音声の取り出し、プレビュー |
| `detect.js` | 打球音の検出、スイング／ラリーの区間計算 |
| `mp4.js` | MP4 / MOV の読み込みと、再エンコードなしの書き出し |
| `worker.js` | 書き出し処理（OPFS へ書き込む Worker） |
| `analyze/` | テニス試合解析の画面 |
| `rally.js` | バウンド・サーブ・フォルト・イン/アウト・ポイントの組み立て |
| `court.js` | コートの位置合わせ（白線・ネットポスト） |
| `ball.js` | ブラウザでのボール検出（WebCodecs + ONNX Runtime Web） |
| `bench/` | ボール検出の速度テスト |
